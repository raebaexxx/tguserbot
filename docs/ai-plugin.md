# Плагин `ai`

Диалог с Gemini и генерация плагинов по описанию.

## Настройка

Ключ лежит **только** в окружении, никогда в репозитории:

```bash
sudoedit /etc/tguserbot/userbot.env
# TGUSERBOT_GEMINI_API_KEY=ваш-ключ
sudo systemctl restart tguserbot
```

Несколько ключей через запятую — они ротируются, что превращает лимит в чуть
медленный ответ вместо ошибки:

```
TGUSERBOT_GEMINI_API_KEYS=ключ1,ключ2,ключ3
```

Имя переменной настраивается (`api_key_env`), если вы ходите через прокси.

## Модели

| Роль | ID | Когда |
|---|---|---|
| диалог и код | `gemini-3.8-flash` | по умолчанию; GA, бесплатный тариф |
| быстрый режим | `gemini-3.5-flash-lite` | `/ub ai fast` — дёшево |
| глубокое рассуждение | `gemini-3.1-pro-preview` | `/ub ai pro`; **не бесплатный** |

Идентификаторы в API отличаются от названий на сайте: `gemini-3.1-pro` в веб-
интерфейсе — это `gemini-3.1-pro-preview` в API. `/ub ai models` показывает, что
доступно **именно вашему ключу**, — надёжнее, чем доверять документации.

Переопределяются в `<data_dir>/plugin-config.toml`:

```toml
[ai]
chat_model = "gemini-3.7-flash"
min_edit_interval = 5.0
```

## Когда модель недоступна

Лимиты бесплатного тарифа считаются **на каждую модель отдельно**, и их два.
Проверено на живом ответе:

```
You exceeded your current quota, please check your plan and billing details. ...
Quota exceeded for metric: generativelanguage.googleapis.com/
generate_content_free_tier_requests, limit: 20, model: gemini-3.8-flash
Please retry in 56.601092868s.
```

Это **20 запросов в минуту**, а не исчерпанная суточная квота. Заголовок один и
тот же в обоих случаях, поэтому судить только по нему нельзя: читается вторая
половина, где API сам называет срок.

Что делает плагин:

| Ситуация | Поведение |
|---|---|
| `Please retry in 1.4s` | повтор на той же модели — ждать недолго дешевле |
| `Please retry in 56s` | переход к следующей модели: минута внутри команды — это вечность |
| срока нет | переход: ждать, скорее всего, до суточного сброса |

Порог в 10 секунд — `SWITCH_AFTER_SECONDS` в `userbot/gemini.py`. Это решение, а не
константа с очевидным ответом, поэтому оно названо и описано там, где стоит.

Дальше цепочка из `model_fallbacks`, и ответившая модель запоминается, чтобы не
платить за `429` на каждом следующем вопросе:

```toml
[ai]
# Сначала та, что вам нужна; остальные — пол.
model_fallbacks = ["gemini-3.8-flash", "gemini-3.7-flash", "gemini-3.5-flash-lite"]
```

Когда ответила не та модель, что настроена первой, плагин пишет это строкой под
ответом — и говорит **что именно** случилось, потому что «квота исчерпана» про
минутный лимит отправляет читателя на страницу биллинга, где всё в порядке:

```
Лимит запросов к gemini-3.8-flash исчерпан (повтор через ~57 с), отвечает gemini-3.7-flash.
```

Когда недоступны все, ошибка называет их. Обычный запуск молчит.

На роутер попадают **только** лимиты и отказы по квоте. `404`, неверный ключ или
заблокированный запрос другая модель не исправит, и искать ответ в другом месте —
просто умножать ошибку.

`chat_model` и `code_model` маршрутизируются раздельно: у каждой роли своя цепочка
и своё запомненное состояние, иначе запрос кода ушёл бы на модель для диалога.

## Команды

```
/ub ai <вопрос>                диалог с историей
/ub ai pro <вопрос>            gemini-3.1-pro-preview
/ub ai fast <вопрос>           gemini-3.5-flash-lite
/ub ai new <имя> <описание>    сгенерировать плагин
/ub ai list                    что ждёт установки
/ub ai show <имя>              файлы и отчёт безопасности
/ub ai models                  модели, доступные ключу
/ub ai reset                   забыть историю
```

## Создание плагина — два шага, и это не формальность

Модель пишет **только** в `<data_dir>/plugin-staging/<имя>/`. Этот каталог не
является корнем плагинов: у него нет собственного `plugin.toml`, поэтому ни
обнаружение, ни наблюдатель его не видят. Сгенерированный код физически не может
запуститься, пока вы не напишете:

```
/ub plugin adopt <имя>
```

При развёртывании выполняется статический разбор, и плагин **отклоняется**, если
он дотягивается до:

- процессов ОС: `subprocess`, `os.system`, `os.popen`, `os.exec*`, `os.fork`, `pty`
- нативного кода: `ctypes`, `cffi`
- выполнения данных: `eval`, `exec`, `compile`, `__import__`, `importlib`
- десериализации: `pickle`, `marshal`, `dill`, `shelve`
- сети в обход ядра: `socket`, `requests`, `httpx`, `urllib`, `aiohttp`,
  `asyncio.open_connection`
- обхода песочницы: `__globals__`, `__subclasses__`, `__builtins__`, `__code__`
- файла сессии Telegram
- удаления файлов и `ctx.client.disconnect()`

Остальные замечания показываются вместе с результатом. Проверка — это
**денylist, а не песочница**: она показывает опасное до запуска, но не изолирует
исполнение. Считайте принятый плагин доверенным — вы его только что одобрили.

Обойти проверку можно (`allow_blocking=True` в коде), но это сделано явным
действием, а не значением по умолчанию.

## Что стоит знать

- **`type=notify` и heartbeat.** Плагин ждёт сеть; при зависании его
  перезапустит watchdog.
- **Ретраи.** `503 UNAVAILABLE` («high demand») — обычное дело, а не авария.
  Клиент повторяет запрос с экспоненциальной паузой и джиттером.
- **Стриминг требует `alt=sse`.** Без этого параметра эндпоинт отдаёт один
  большой JSON-массив в самом конце, а не поток.
- **`thoughtSignature`.** Модель возвращает подпись, которую нужно вернуть в
  следующем ходе. Плагин хранит её в истории; без неё качество диалога падает.
- **Правки сообщения тротттятся** (`min_edit_interval`, по умолчанию 3 с).
  Telegram считает правки, и редактирование на каждый токен — это ровно тот
  способ получить rate limit, который уже случался в этом проекте.
- **История стоит токены.** Каждый ход переотправляется целиком, поэтому
  `max_history_turns` — главный рычаг стоимости.
