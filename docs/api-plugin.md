# Плагин `api`

Чат, генерация изображений, расшифровка голосовых и пересказ видео через
бесплатные OpenAI-совместимые API, которые публикуются в открытом канале
(`@zk_ichinokata` по умолчанию).

Ключи в канале меняются постоянно: новые посты выходят десятками за день, и
живут они недолго. Плагин относится к ним соответственно — собирает каталог,
проверяет свежие ключи, ротирует их при отказах и никогда не полагается на
один.

## Откуда берутся ключи

Каждое сообщение канала описывает одно предложение:

```
🌐 Base URL: https://api.groq.com/openai/v1

🔑 Ключ: gsk_...

📅 Дата: 2026-10-16 07:06 UTC
📊 Тир: 8k tok/min (мелкий)

🧩 Модели:

✅ Работают: openai/gpt-oss-120b
🔒 Нет доступа (403): ⭐ claude-sonnet-5
📋 Листятся: allam-2-7b, whisper-large-v3, whisper-large-v3-turbo … (+14 ещё)
```

Парсер читает эту структуру целиком: адрес, ключ, дату, тир и три списка
моделей. Пометка канала «✅ Работают» используется как подсказка для
ранжирования, но не как гарантия — гарантий тут нет ни у чего. Посты,
отредактированные до «SOMETHING HAS BEEN HERE!», пропускаются, а не
угадываются.

Посты приходят **в реальном времени** — плагин подписывается на канал при
первом запуске (`join_on_setup = true`), слушает новые сообщения и тут же
кладёт их в каталог. Первый запуск дополнительно вычитывает последние 100
постов. Если подписка нежелательна, поставьте `join_on_setup = false` и
пользуйтесь `/ub api refresh`.

## Команды

```
/ub api <вопрос>              чат (стриминг, история, автопереключение)
/ub api img <промпт>          сгенерировать изображение
/ub api (ответом)             ответить на голосовое / видео / фото
/ub api models [фильтр]       что есть в каталоге: модель, теги, живые ключи
/ub api keys                  состояние ключей по провайдерам
/ub api use <модель|провайдер> закрепить выбор; use auto — вернуть автопилот
/ub api refresh [N]           перечитать последние N постов канала
/ub api test <модель>         живой тест: один запрос и время ответа
/ub api reset                 очистить историю диалога
```

Ответом на медиа-сообщение:

- **голосовое** — расшифровка; если добавить текст вопроса, он уйдёт в чат
  вместе с расшифровкой («что тут важного?»);
- **видео/видеокружок** — пересказ: речь по транскрипту, картинка по кадрам,
  затем один общий связный текст (просите фокус, например «в конце видео»);
- **фото** — визуальный ответ на вопрос или короткое описание.

## Как выбирается модель

Автопилот ранжирует кандидатов:

1. закреплённое через `/ub api use` — всегда первым;
2. приоритет провайдеров из `provider_priority`;
3. проверенные ключи раньше непроверенных;
4. «✅ Работают» и ⭐ раньше остальных;
5. свежие посты раньше старых; меньше отказов раньше больше.

Отказы запоминаются: `401` — кулдаун ключу (шесть часов), `403` — кулдаун
паре ключ+модель, `404` — сутки, `429` — минута (или честный срок из ответа
API). Кулдауны **исключают** кандидата: спрашивать ключ, который только что
ответил отказом, — значит тратить запрос, которым ответила бы другая модель.
Если API назвало короткую паузу (до 10 секунд), плагин подождёт и повторит
тот же ключ; всё, что дольше, — повод переключиться, а не ждать.

Когда ответила не первая модель, под ответом появляется строка об этом —
молчаливая подмена читалась бы как «всё работает».

## Проверка ключей

Каждый новый ключ проходит одну активную пробу: `GET /models` (реальный
список моделей, токены не тратятся) и один chat-запрос на один токен, чтобы
убедиться, что ключ жив. Проба намеренно дешёвая: это бесплатные квоты, и
глубокая проверка всех медиа-моделей при каждом обновлении сжигала бы их
ежечасно. Медиа-возможности определяются по именам моделей
(`whisper-…` → речь, `…-vision-…` → зрение, `…image…` → генерация) и
проверяются по факту первого использования, а не заранее.

## Медиа и приватность

Медиа **включено по умолчанию** — это и есть фича плагина, — но отличается от
`sum` тем, что об этом говорится: первое медиа-сообщение один раз
напоминает, что байты ушли на публичный сторонний API. Выключить целиком:
`media_enabled = false`.

Лимиты намеренно скромные, потому что `/tmp` у юнита — это tmpfs (RAM), а
`MemoryMax=1G`:

| Что | По умолчанию |
|---|---|
| Видео | 50 МБ |
| Голосовое/аудио | 20 МБ |
| Изображение | 10 МБ |
| Кадров из видео | 6, ширина 512 px |

Видео без звуковой дорожки всё равно пересказывается — по кадрам; кадры
дедуплицируются по хэшу (шесть одинаковых картинок — это пять лишних
запросов к зрению). `ffmpeg` обязателен для видео. Если какая-то стадия
недоступна, плагин честно пишет, какие данные удалось собрать.

## Настройка

Всё переопределяется в `<data_dir>/plugin-config.toml`:

```toml
[api]
channel = "zk_ichinokata"
join_on_setup = true
media_enabled = false
provider_priority = ["groq", "nvidia", "mistral", "minimax", "agnes"]
initial_scan = 100
max_history_turns = 12
min_edit_interval = 3.0
validation_concurrency = 3
video_max_bytes = 52428800
video_frames = 6
```

Приоритет провайдеров — единственный содержательный рычаг качества: у
бесплатных ключей разные лимиты и скорость, и первые в списке отвечают чаще.

## Что стоит знать

- **Ключи умирают.** Канал ротирует их сам; плагин не чистит каталог
  агрессивно, а помечает отказы кулдаунами, поэтому мёртвый ключ перестаёт
  мешать в течение одного отказа.
- **Смена провайдера — это смена канала.** Новый хост в постах работает без
  правок в коде: маппинг провайдеров знает основные домены, остальные
  берутся как есть.
- **История стоит токенов.** Каждый ход переотправляется; `max_history_turns`
  — главный рычаг. История не заполняется вопросом, на который не ответили.
- **Плагин не песочница для канала.** Каталог ограничен тем, что канал
  опубликовал; но это чужие API и чужие ключи — не отправляйте через них то,
  что не готовы увидеть на третьей стороне, и держите `media_enabled` под
  контролем.
